# Enshrouded — приватный сервер «только по Steam64 ID, все как Admin, без паролей»

Мод для **выделенного сервера Enshrouded** (Windows). Делает сервер приватным:
пускает только перечисленные вами SteamID64, и все они заходят как **Admin**
без ввода пароля.

Работает как прокси-`steam_api64.dll`: перехватывает Steam-проверку входящего
игрока (`ISteamGameServer::BeginAuthSession`) и отклоняет всех, кого нет в списке.
**Внутренности `enshrouded_server.exe` не трогаются вообще** — поэтому мод
устойчив к обновлениям игры.

Проверено на структуре серверного билда с интерфейсом Steam `SteamGameServer015`.

---

## Как это устроено (коротко)

1. **Беспарольный Admin.** В `enshrouded_server.json` одна-единственная группа —
   `Admin` с `"password": ""` и всеми правами. Игра **нативно** допускает одну
   беспарольную группу; ограничение «беспарольная группа не может иметь больше
   прав, чем парольная» при единственной группе выполняется само собой, так что
   конфиг проходит штатную проверку без патчей. Любой, кто входит без пароля,
   попадает в эту группу → становится Admin.

2. **Приватность.** Поскольку беспарольный Admin пустил бы вообще всех, фильтрацию
   делает прокси-DLL: на каждый вход она сверяет SteamID64 игрока со списком
   `enshrouded_whitelist.txt`. Нет в списке → возвращается «невалидный билет»,
   сервер отклоняет подключение.

## Сборка через GitHub Actions (проще всего)

В репозитории есть workflow `.github/workflows/build.yml`: при каждом пуше он
собирает `steam_api64.dll` на `windows-latest` (MSVC) и кладёт её в артефакты.

1. Запушьте репозиторий на GitHub (если ещё не).
2. Вкладка **Actions** → прогон **build-proxy-dll** (или нажмите **Run workflow**).
3. По завершении внизу страницы прогона → блок **Artifacts** → скачайте
   **`steam_api64-proxy`** → внутри готовая `steam_api64.dll`.

Локально собирать не обязательно. Если всё же нужно — см. ниже.

## Сборка локально

Готовую DLL приложить не могу — соберите у себя (пара минут). Два пути:

### Вариант 1 — MSVC (рекомендую, самый простой)
1. Поставьте **Visual Studio Build Tools** (бесплатно): инсталлятор →
   компонент **«Разработка классических приложений на C++»**.
   (Полная Visual Studio Community тоже подойдёт.)
2. Откройте **«x64 Native Tools Command Prompt for VS»** (из меню Пуск).
3. `cd` в папку с этими файлами и запустите:
   ```
   build_msvc.bat
   ```
   Получится `steam_api64.dll`.

### Вариант 2 — MinGW-w64
Если у вас уже есть MinGW-w64 (например, через MSYS2: `pacman -S mingw-w64-x86_64-gcc`):
```
./build_mingw.sh
```

## Установка (на машине сервера)

В папке сервера (там, где `enshrouded_server.exe`):

1. **Переименуйте оригинал:** `steam_api64.dll` → `steam_api64_org.dll`
   ⚠️ Обязательный шаг. Прокси пересылает все вызовы Steam в этот переименованный
   оригинал. Не удаляйте его.
2. **Положите рядом собранную** `steam_api64.dll` (нашу прокси).
3. **Положите рядом** `enshrouded_whitelist.txt` и впишите SteamID64 (по одному в
   строке; 17-значные числа вида `7656119...`). SteamID64 можно получить на
   steamid.io или steamdb.info/calculator.
4. **Замените** `enshrouded_server.json` на приложенный (или вручную оставьте в
   `userGroups` только одну группу `Admin` с `"password": ""`). Если нужен — поправьте
   `name`, `slotCount`, `gameSettings` под себя; трогать `userGroups` не надо.
5. Запустите сервер. Дождитесь в консоли `Host_Online`.

Итоговая раскладка файлов:
```
enshrouded_server.exe
steam_api64.dll          ← прокси (собранная вами)
steam_api64_org.dll      ← переименованный оригинал Steam
enshrouded_whitelist.txt ← ваш список SteamID64
enshrouded_whitelist.log ← появится сам, журнал решений (ALLOW/DENY)
enshrouded_server.json   ← одна беспарольная Admin-группа
```

## Проверка

- При входе игрока в `enshrouded_whitelist.log` появляется строка `ALLOW SteamID64=...`
  или `DENY SteamID64=...`. По ней сразу видно, что фильтр работает и какой ID
  пришёл (удобно, если кого-то по ошибке не пустило — скопируйте ID из `DENY` в список).
- Список **перечитывается на лету** при сохранении файла — перезапуск сервера не нужен.
  Строку `INFO whitelist loaded: N entries` тоже увидите в логе.
- Клиент при входе на сервер с беспарольной группой пароль не спрашивает.
  Если вдруг в вашем билиде всё же появится окно ввода — просто оставьте поле пустым
  (вход всё равно пройдёт в единственную группу).

## Обновления игры / Steam

- **Обновление Enshrouded** переустанавливает `steam_api64.dll` из Steam, то есть
  **возвращает оригинал на место и затирает прокси**. После каждого апдейта повторите
  шаги установки 1–2 (переименовать новый оригинал → положить прокси). `.json`,
  whitelist и собранная DLL остаются прежними. Удобно завести `.bat`, который делает
  эти два `move`/`copy` автоматически после `steamcmd ... validate`.
- Логика `enshrouded_server.exe` при этом не важна — мод к ней не привязан.
- **Если Steam сменит версию интерфейса** (условно `SteamGameServer016`) и вход
  начнёт пропускать всех без разбора — значит сместился слот vtable. Тогда:
  1) дизассемблируйте `SteamAPI_ISteamGameServer_BeginAuthSession` в новой
     `steam_api64_org.dll` (`mov rax,[rcx]; jmp [rax+0x??]`), возьмите смещение `0x??`;
  2) впишите его в `VTBL_OFFSET_BeginAuthSession` в `dllmain.cpp` и пересоберите.
- **Если сервер не стартует с ошибкой про отсутствующий экспорт** после апдейта Steam —
  перегенерируйте таблицу форвардов: `python gen_def.py <новая steam_api64.dll> > steam_api64.def`
  и пересоберите.

## Файлы в комплекте

| Файл | Назначение |
|---|---|
| `dllmain.cpp` | исходник прокси-DLL (вся логика whitelist + хук) |
| `steam_api64.def` | таблица экспортов прокси (форвард 1063 функций + 1 хук) |
| `enshrouded_server.json` | готовый конфиг: одна беспарольная Admin-группа |
| `enshrouded_whitelist.txt` | ваш список SteamID64 (пример внутри) |
| `build_msvc.bat` | сборка под MSVC |
| `build_mingw.sh` | сборка под MinGW-w64 |
| `gen_def.py` | перегенерация `steam_api64.def` после апдейтов Steam |

---

## Важно

- Это серверный мод для **вашего собственного** сервера; клиентам ничего ставить не
  нужно, модифицированные файлы есть только на сервере.
- Держите `steam_api64_org.dll` рядом — без него прокси не запустит Steam и сервер
  не поднимется.
- Пустой или отсутствующий whitelist = никого не пускать (так безопаснее). Это видно
  в логе предупреждением.
